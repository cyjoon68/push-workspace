# 확정 UI 구현 기준

참조: `no-right-sidebar-prototype-v6.png`, 1672×941. 원본 레이아웃을 그대로 기준으로 삼으며 새로운 콘셉트 이미지를 생성해 대체하지 않는다.

## 셸

- 좌측 폭 약 294px(1672px 화면 기준), 콘텐츠와 1px 경계. 화면 높이 전체를 사용한다.
- 배경은 무채색 어두운 표면: 중앙 약 #1f1f1e, 좌측 약 #2c2c2b, 테두리 약 #414140. 강조는 보라색, 기본 텍스트는 밝은 회색이다.
- OS 네이티브 창 장식을 활성화한다(`decorations: true`). 닫기·최소화·전체 화면 버튼은 OS가 제공하며 HTML/CSS로 모방하지 않는다. 사이드바 접기는 별도 앱 기능으로 유지한다. 본문 상단에는 Push 표시, 회사/작업 제목과 작업 액션을 둔다.
- 사이드바 섹션은 `기능`, `채팅`, `프로젝트`. 기능은 `지원 현황`, `내 서류`, `캘린더`, `면접 준비`.
- 선택 행은 얇은 보라색 왼쪽 표시와 회색 배경. 프로젝트와 채팅은 실제 저장 데이터로 채운다. 샘플 회사·성과를 사용자 사실로 저장하지 않는다.
- 오른쪽 사이드바는 없다. 중앙 캔버스는 남은 폭 전체를 사용한다.
- 원본의 윤곽선 아이콘을 일관된 획·크기로 구현한다. 버튼·입력·라벨 글꼴을 명시하고 macOS 한글 시스템 글꼴을 사용한다.

## 작업 캔버스

본문은 중앙에서 읽기 좋은 폭을 사용하며 채팅 입력창은 하단에 놓는다. 사용자 발화는 오른쪽, 분석 응답·문서 카드·승인 행은 왼쪽이다. 문서 열기/변경 검토/승인은 실제 선택 문서와 승인 대상을 사용한다.

입력창에는 추가, 실행 권한, AI 모델, 작업 강도, 전송을 표시한다. 실행 권한 설정이 개별 제출·CLI·근거·문서 확정 승인을 대체하지 않는다. 사용할 수 없는 외부 기능은 실제 미설정 상태와 다음 동작을 보여주며 성공 응답을 만들지 않는다.

## 원본에 없는 필수 상태

계획의 근거 수집, 공고 등록, 문서 편집, 캘린더, 면접, 오퍼, CLI, 설정은 같은 셸·타이포그래피·행/폼 스타일로 확장한다. 기능 수행에 필요한 입력과 오류 메시지 외에 임의의 성과 지표나 제품 홍보 문구를 추가하지 않는다. 빈 상태에서 시작할 수 있어야 하며 확인 가능한 테스트 데이터가 있을 때만 참조의 채팅 구성을 재현한다.

축소 창에서는 사이드바를 접고 본문이 가로로 넘치지 않아야 한다. 모든 아이콘 버튼은 접근 가능한 이름, 키보드 포커스, Tab 이동을 제공한다. 밝은 테마/어두운 테마/시스템 테마와 한국어/영어 전환을 지원한다.

## 검증 기록

최종 실행본 스크린샷과 원본을 같은 검증 회차에서 직접 열어 다음 다섯 항목 이상을 비교한다: 사이드바 폭/밀도, 라벨/선택 행, 중앙 폭/상하 여백, 표면/보라색, 글꼴/컨트롤 크기, 축소 창. 정적 이미지는 폼 저장·문서 버전·승인·출력·오프라인 동작의 증거가 될 수 없다.
